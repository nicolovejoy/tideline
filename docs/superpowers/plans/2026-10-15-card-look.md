# The app in the share card's look

Nico saw the share card (`public/og.png`, drawn from `docs/link-preview.svg`) on 2026-10-15 and asked for the app to look and work like it. The card is the app's own tide panel in its dark palette, with a big title and a subtitle, and the Sunset and Moonrise lines labelled. The design was agreed in chat on 2026-10-15 (bounded, no spec): the dark palette becomes the only palette and light mode goes (Nico's decision, option 1 of 3); "Tideline" becomes the title with the spot named in a muted line under it; the tide panel's Sunset and Moonrise lines are labelled at the top; the tide panel grows a little. Everything else keeps its look.

## Global constraints

- Code style is the Vite template's: no semicolons, single quotes, relative imports carry their `.ts`/`.tsx` extension, type-only imports use `import type`, no enums. `npm run lint` (oxlint, then Prettier) and `npm run build` (type-check) must pass; run `npm run format` before committing.
- Components hold no arithmetic, no rules and no wording. Those live in plain modules with tests. Tests run with `TZ=Asia/Tokyo`.
- Node 24: in a fresh shell, `source ~/.nvm/nvm.sh && nvm use`.
- Comments say why, in plain words, as the existing ones do. No marketing words.
- The share card itself (`public/og.png`, `docs/link-preview.svg`) does not change.
- Commit each task on the branch `feat/card-look` with a message in the repo's style (a sentence, present tense, what and why) ending in the line `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

/**

export function spotSubtitle(
  spot: Pick<Spot, 'name' | 'elevationFt' | 'nws' | 'tideStation'>,

  return hasTides(spot)

}

## Task 2: Labelled event lines, and a taller tide panel

Files: `src/chart/scales.ts`, `src/chart/scales.test.ts`, `src/chart/Panel.tsx`, `src/ui/selection.ts`, `src/ui/selection.test.ts`, `src/ui/SpotScreen.tsx`, `src/styles.css`.

**Which side the label stands.** In `src/chart/scales.ts`, a new exported function, with tests in `src/chart/scales.test.ts` written first:

```ts
/**
 * Which side of a vertical line its label stands on: to the right, unless
 * the line is in the last fifth of the width, where the label would run
 * off the plot.
 */
export function labelSide(x: number, width: number): 'left' | 'right' {
  return x > width * 0.8 ? 'left' : 'right'
}
```

Tests: `labelSide(100, 400)` is `'right'`; `labelSide(320, 400)` is `'right'` (exactly the boundary); `labelSide(321, 400)` is `'left'`.

**The marker's label.** In `src/chart/Panel.tsx`, `Marker` gets an optional `label?: string` with the doc comment `/** Its name, drawn at the top beside the line, where the panel is the one to carry it. */`. Where the markers are drawn, each one with a `label` gets, after its `<line>`, a `<text>` in the same `<g>` (wrap line and text in a `<g key={marker.name} className={`marker marker-${marker.name}`}>`; the `line` keeps no class of its own and the CSS below is adjusted so the stroke applies to the group's line):

```tsx
{marker.label !== undefined && (
  <text
    className="marker-label"
    x={side === 'right' ? x(marker.t) + 6 : x(marker.t) - 6}
    y={LABEL_Y}
    textAnchor={side === 'right' ? 'start' : 'end'}
  >
    {marker.label}
  </text>
)}
```

with `const side = labelSide(x(marker.t), width)` computed per marker and `const LABEL_Y = 12` at the top of the file, commented: `/** Where a marker's label sits: in the headroom above the highest value. */`. `labelSide` is imported from `./scales.ts`.

**Which markers are labelled.** In `src/ui/selection.ts`, `dayMarkers` returns `{ name: 'sunset', t: sunset, label: 'Sunset' }` and `{ name: 'moonrise', t: moonrise, label: 'Moonrise' }`; the `now` marker has no label. Its return type becomes `Marker[]`, imported with `import type { Band, Marker } from '../chart/Panel.tsx'`. Update the three existing `dayMarkers` tests: the first's `toEqual` gains the two labels; the other two map over `name` and need no change. Add one test: `'the sunset and moonrise lines carry their names; the current time does not'`, asserting `labels` of today's markers equal `[undefined, 'Sunset', 'Moonrise']`.

Also in `selection.ts`, a new exported function with a test:

```ts
/** The same lines without their labels, for the panels that do not carry them. */
export function unlabelled(markers: Marker[]): Marker[] {
  return markers.map(({ name, t }) => ({ name, t }))
}
```

Test: `unlabelled(dayMarkers(today, NOW))` equals the three markers with no `label` key.

**The tide panel carries the labels.** In `src/ui/SpotScreen.tsx`, the tide `Panel` keeps `markers={markers}` and `WeatherPanels` gets `markers={unlabelled(markers)}`, with `unlabelled` added to the import from `./selection.ts`. `TIDE_HEIGHT` becomes `200`, and `HEADROOM` becomes `26`, with its comment: `/** Room above the highest tide for a rule's label and the event lines' names. */`.
