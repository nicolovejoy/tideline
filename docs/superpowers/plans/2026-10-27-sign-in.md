# Sign In and Out Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A user signs in to Tideline with Google by popup and signs out, from a tab or the home-screen app, the state kept between opens, with nothing else in the app changing.

**Architecture:** One framework-free adapter (`src/data/firebase.ts`) is the only file that imports the Firebase SDK, and imports it dynamically so it is a chunk of its own. A pure module (`src/ui/accountView.ts`) holds every word and rule; a hook (`src/ui/useAccount.ts`) ties the two; a component (`src/ui/Account.tsx`) arranges one row under the spot's line in `App.tsx`. `vercel.json` and a Vite proxy serve Firebase's auth handler from the page's own host.

**Tech Stack:** Vite 8, React 19, strict TypeScript, Vitest 5, `firebase` ^13.1.0 (modular `firebase/app`, `firebase/auth`).

**Spec:** `docs/superpowers/specs/2026-10-27-sign-in-design.md`

## Global Constraints

- Code style: no semicolons, single quotes, relative imports with `.ts`/`.tsx`, `import type`, no enums. `npm run lint` (oxlint, then Prettier) must pass; run `npm run format` before committing.
- Tests run with `TZ=Asia/Tokyo`; nothing here reads a time, so nothing may depend on the zone either.
- Components hold no arithmetic, no rules and no wording. Every word is in `src/ui/accountView.ts`.
- `firebase/*` is imported in `src/data/firebase.ts` only, and only dynamically (`await import(...)`).
- Env names, exactly: `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID`, `VITE_FIREBASE_AUTH_DOMAIN`. Project id `tideline-ibuild4you`. Rewrite destination `https://tideline-ibuild4you.firebaseapp.com/__/auth/:path*`.
- Storage flag key, exactly: `tideline:account:seen`. Every storage access is wrapped in try/catch, as `src/ui/choices.ts` does.
- The account row is always one line tall; the chips under it never move.
- Commit messages: a sentence in the repo's voice, ending with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- Never read `.env.local` or any `.env` file but `.env.tpl`.

## Review Focus

- Storage disabled or full (private browsing): the flag's read gives false and its write does nothing; the row still works for the open. Test in Task 2.
- A second tap on "Sign in with Google" while the first popup is open: the SDK throws `auth/cancelled-popup-request`; the row must show nothing and go back to the button, not a sentence. Test in Task 2.
- An error object that is not a Firebase error (no `code`): worded as "Sign-in did not finish. Try again." with no code in brackets, never a crash. Test in Task 2.
- A user whose Google account has no email (`user.email` null): the row shows "Signed in" rather than an empty string. Test in Task 2.
- The flag set but Firebase reports no user (signed out elsewhere, storage cleared by iOS): the row goes to the button and the flag is removed, with no error line. Browser check in Task 4: set the flag by hand in DevTools with Firebase signed out, reload.

### Task 2: The account view: words, states, errors, the start-up flag

**Files:**
- Create: `src/ui/accountView.ts`, `src/ui/accountView.test.ts`

**Interfaces:**
- Produces:
  - `type AccountUser = { email: string | null }`
  - `type Account = { kind: 'out' } | { kind: 'loading'; tapped: boolean } | { kind: 'in'; email: string | null } | { kind: 'failed'; words: string }` — `tapped` is true when a tap started the load, false at start-up.
  - `const WORDS = { signIn: 'Sign in with Google', signingIn: 'Signing in…', signOut: 'Sign out', loading: '…', noEmail: 'Signed in', spotsStay: 'Your spots stay on this device for now.' } as const`

  - `function loadingWords(tapped: boolean): string` — `WORDS.signingIn` when tapped, else `WORDS.loading`.
  - `function failureWords(error: unknown): string | null` — null for `auth/popup-closed-by-user` and `auth/cancelled-popup-request`; the spec's sentence for `auth/popup-blocked`, `auth/network-request-failed`, `auth/unauthorized-domain`; `Sign-in did not finish. Try again. (<code>)` for any other string code; `Sign-in did not finish. Try again.` for an error with no code. A Firebase error is `{ code: string }`; read it as `(error as { code?: unknown }).code`.
  - `const NOT_SET_UP = 'Sign-in is not set up in this build.'`
  - `function readSeen(): boolean`, `function writeSeen(): void`, `function clearSeen(): void` — the flag `tideline:account:seen` in `localStorage`, wrapped like `src/ui/choices.ts`.
  - `function startsSignedIn(seen: boolean): boolean` — identity, named so `App` reads as the rule: load the SDK at start-up only where the flag is set.

### Task 3: The Firebase adapter

**Files:**
- Create: `src/data/firebase.ts`

**Interfaces:**
- Consumes: `firebaseConfig` from Task 1; `AccountUser` from Task 2.
- Produces:
  - `class NotConfigured extends Error` with `missing: string[]`.
  - `function watchUser(listener: (user: AccountUser | null) => void): () => void` — starts the SDK on first call, calls `listener` on every auth change (via `onAuthStateChanged`), returns the unsubscribe. If the config is missing, calls `listener(null)` once and returns a no-op. If the SDK import fails, rejects nothing: calls `listener(null)` and returns a no-op (the hook falls back to the button).
  - `function signIn(): Promise<AccountUser>` — `signInWithPopup(auth, new GoogleAuthProvider())`; resolves `{ email: user.email }`; throws `NotConfigured` when the config is missing; otherwise rethrows the SDK's error.
  - `function signOut(): Promise<void>`.

- [ ] **Step 1: Implement** `src/data/firebase.ts`. One lazily-created promise `ready(): Promise<{ auth: Auth } | NotConfigured>` that does `const [{ initializeApp }, authMod] = await Promise.all([import('firebase/app'), import('firebase/auth')])`, builds the app from `firebaseConfig(import.meta.env, window.location.host)`, and memoises. `watchUser` is async inside: it awaits `ready()` and subscribes; the returned function unsubscribes once the subscription exists, or marks it so the subscription is dropped on arrival. Types `Auth` and `User` as `import type` from `firebase/auth` are allowed (types are erased; the rule is about the runtime import). Head comment: the only file that touches Firebase; loaded on demand so the forecast page does not pay for it; why the auth domain is the page's host.

- [ ] **Step 2: Verify**: `npm run build` passes and `dist/assets/` now has a chunk whose name does not start with `main-` or `AddSpot-` and that is at least 90 kB (the SDK), and `main-*.js` grew by under 5 kB. `npx tsc -b` clean. Nothing imports the adapter yet, so if Vite drops it from the build, run `npx tsc -b` alone and take that as the check.

- [ ] **Step 3: Lint and commit** `src/data/firebase.ts`: "The Firebase adapter: sign in by popup, sign out, and watch the user, with the SDK loaded only when first used".
